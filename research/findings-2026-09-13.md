### 2026-09-13 — SOTA Test-Time Compute Scaling for Program Synthesis

**Subagent question:** What is the actual state of the art in test-time compute scaling for program synthesis as of mid-2026? Verify claims about ReST-MCTS*, S*, CodeT.

**Answer:**

**CRITICAL FINDING: ReST-MCTS* does NOT evaluate on code at all.** It is purely a math/science reasoning paper. The paper explicitly acknowledges code as future work in its Limitation section: "we need to show the ReST-MCTS* can generalize to other reasoning tasks outside of math (like coding, agent, etc)."

**CRITICAL FINDING: S* is NOT MCTS-based.** The paper explicitly states: "our work applies hybrid scaling to code generation tasks without relying on tree search methods, as developing a general and effective reward model for the code generation domain remains challenging." S* uses parallel sampling + iterative debugging + adaptive pairwise selection.

Key papers verified:

1. **ReST-MCTS*** (NeurIPS 2024, arXiv:2406.03816)
   - Venue: NeurIPS 2024 (confirmed from arXiv comments)
   - Citation count: UNVERIFIED (API rate limited)
   - **Does NOT evaluate on HumanEval or any code benchmark**
   - Benchmarks: MATH, SciBench, GSM8K, GPQA Diamond, CEval-Hard
   - Requires trained PRM (Process Reward Model) initialized from ChatGLM3-6B or Mistral-7B
   - Models: SciGLM-6B, LLaMA-3-8B-Instruct, Mistral-7B
   - Best MATH result: 48.5% (Figure 2a)
   - Code: https://github.com/THUDM/ReST-MCTS

2. **S*** (arXiv:2502.14382, Feb 2025 preprint — NOT published at a venue)
   - LiveCodeBench v2 results (Table 1):
     - Qwen2.5-Coder-0.5B-Instruct: 1.2% → 10.9%
     - Qwen2.5-Coder-1.5B-Instruct: 7.0% → 27.6%
     - Qwen2.5-Coder-3B-Instruct: 18.4% → 42.7%
     - Qwen2.5-Coder-7B-Instruct: 29.4% → 54.4%
     - DeepSeek-R1-Distill-Qwen-32B: 69.1% → 85.7%
   - Does NOT require trained reward model — uses execution-based selection
   - Uses GPT-4o-mini for pairwise selection (API dependency)
   - Compute: "Experiments with the largest model takes one day on 8 H100 GPUs"
   - Code: https://github.com/NovaSky-AI/SkyThought

3. **CodeT** (ICLR 2023, arXiv:2207.10397)
   - 607 citations (Semantic Scholar, verified)
   - HumanEval pass@1: 65.8% using code-davinci-002 (+18.8% over base)
   - No training required — uses same model for code + test generation
   - Dual execution agreement for filtering

4. **RethinkMCTS** (EMNLP 2024, arXiv:2409.09584) — 36 citations
   - MCTS in thought/reasoning space, not code space
   - Fine-grained execution feedback for thought refinement

5. **SRA-MCTS** (IJCAI 2025, arXiv:2411.11053) — 13 citations
   - Self-driven reasoning augmentation via MCTS before code generation
   - No external supervision required

Smallest model with meaningful MCTS results for code: Qwen2.5-Coder-3B-Instruct (18.4% → 42.7% via S*). The 0.5B model only reaches 10.9% on LiveCodeBench with S*.

**The "selection bottleneck" is the key unsolved problem:** A 2026 paper (arXiv:2608.18931) finds that reward models correlate at only rho ~= 0.12 with true quality on open-ended tasks.

**Evidence:** arXiv papers fetched and parsed directly. ReST-MCTS* limitations section verified from HTML. S* results table verified from HTML.

**Not verified:** Exact citation counts for ReST-MCTS* and S* (API rate limited). Exact benchmark numbers for RethinkMCTS and SRA-MCTS.

**Contradictions/resolution:** The other AI claimed ReST-MCTS* evaluates on code (559 citations) and that S* uses MCTS. Both claims are factually wrong per the papers themselves.

**Other discoveries:**
- The practical floor for MCTS on code appears to be ~3B parameters
- S* relies on GPT-4o-mini API for selection — not fully self-contained
- CodeT (ICLR 2023, 607 citations) is the most influential test-time scaling paper for code
- "Test-Time Scaling in the Wild" (Aug 2026) finds reward model correlations are very low for open-ended tasks

### 2026-09-13 — HDC/VSA in Program Synthesis

**Subagent question:** Has anyone used HDC/VSA for program synthesis or as a process reward model?

**Answer:**

**The "nobody has done this" claim is partially refuted.** The Doug paper (arXiv:2510.16533, Oct 2025) directly combines VSA with program synthesis. GWT has been published at ICLR 2022 by Yoshua Bengio's group.

1. **Doug** (MathPsych/ICCM 2025, arXiv:2510.16533)
   - Directly combines VSA with program synthesis
   - Encodes program types as VSA hypervectors via Holographic Declarative Memory
   - Uses "Lisp VSA" (Tomkins-Flanagan & Kelly 2024) for encoding program terms
   - Type system (LLFPL) restricts programs to polynomial time
   - Proposes neural network learning to predict VSA type vectors to constrain program search
   - References ACT-R, Soar cognitive architectures
   - Code: https://github.com/eilene-ftf/doug
   - Published at cognitive science venue, NOT a top ML venue

2. **GWT at ICLR 2022**
   - "Coordination Among Neural Modules Through a Shared Global Workspace" (arXiv:2103.01197)
   - Authors include Yoshua Bengio
   - Bandwidth-limited shared workspace for module coordination
   - Shows capacity limitations encourage specialization and compositionality
   - At a top ML venue — establishes GWT is publishable

3. **VSA + program synthesis: specifically 2 papers on arXiv** (Doug + one unrelated)
4. **HDC as reward signal: NO direct prior art found**
5. **GWT + program synthesis: 0 results on arXiv**

**BSC limitations for programs:**
- Capacity: limited number of items before crosstalk
- Depth: recursive/nested binding accumulates noise
- Information rate: 0.60-1.40 bits/dimension
- MCR (Modular Composite Representations) can match BSC with 4x less memory

**Evidence:** arXiv searches (0 results for "hyperdimensional computing program synthesis"), Doug paper fetched and parsed, Bengio GWT paper confirmed from arXiv.

**Not verified:** HDC + RL literature (rate limited). Complete cognitive architecture + program synthesis intersection (DBLP blocked). Plate (2003) HRR book claims.

**Contradictions/resolution:** Other AI claimed "Nobody has used a cognitive architecture to guide search for program synthesis" — REFUTED by Doug paper and Newell (1990) Soar work. Other AI claimed "HDC as PRM is completely novel" — PARTIALLY supported but overstated given Doug's VSA-guided synthesis.

**Other discoveries:**
- VSAs are proven Cartesian closed (can express Turing-complete language in fixed dimensions)
- The Heim framework (arXiv:2304.03335) provides static analysis for BSC accuracy bounds
- Dehaene et al. (2022) found neural representations for skills have information content of optimal programs

### 2026-09-13 — Training-Free AI at Top Venues

**Subagent question:** What genuinely training-free systems have been published at NeurIPS/ICML/ICLR 2024-2026?

**Answer:**

**CRITICAL FINDING: Every "training-free" NeurIPS paper uses a frozen PRETRAINED model.** No paper achieves strong results from a system that was never trained on any neural parameters. The claim is always "training-free adaptation/deployment" not "training-free from scratch."

Key papers:

1. **Many-Shot ICL** (NeurIPS 2024 Spotlight, arXiv:2404.11018) — Strongest verified "no-training" result. Frozen LLM with 100s-1000s of examples matches fine-tuning.

2. **Scaling LLM Test-Time Compute** (Snell et al., arXiv:2408.03314) — Small model outperforms 14x larger model. Venue NOT confirmed at NeurIPS/ICML/ICLR.

3. **LLMs Can't Self-Correct Reasoning Yet** (ICLR 2024, arXiv:2310.01798) — KEY NEGATIVE RESULT: Intrinsic self-correction without external feedback FAILS. Performance can degrade. Constrains what training-free self-improvement can achieve.

4. **LLM-Modulo Frameworks** (ICML 2024, arXiv:2402.01817) — Position paper: LLMs as candidate generators + symbolic verifiers provide correctness. Well-received at top venue.

5. **Eureka** (ICLR 2024, arXiv:2310.12931) — GPT-4 generates reward CODE (programs), evolutionary optimization. Outperforms human expert reward design on 83% of 29 tasks.

6. **G-Memory** (NeurIPS 2025) — Self-improving via hierarchical graph memory. +20.89% success rate without modifying frameworks.

7. **MEMORYLLM** (ICML 2024) — Fixed-size memory pool in transformer latent space. Nearly a million updates with no degradation.

**Cognitive architectures at ML venues: ABSENT.** No ACT-R, SOAR, or GWT papers found at NeurIPS/ICML/ICLR 2024-2026 (except Bengio's ICLR 2022 GWT paper). ML community's version = memory-augmented LLM agents.

**Self-improving without weight updates = memory accumulation.** Pattern: G-Memory, PANDA, Voyager's skill library, EpicStar all improve by accumulating structured experience in external stores.

**Evidence:** arXiv searches, Semantic Scholar API, paper HTML parsed.

**Not verified:** LATS venue (92.7% HumanEval, may be ICML 2024 but unconfirmed). Complete NeurIPS 2025-2026 proceedings.

### 2026-09-13 — Feasibility on Limited Compute

**Subagent question:** What is realistically achievable on laptop CPU + Kaggle T4?

**Answer:**

Qwen2.5-Coder-0.5B runs trivially on T4 (~1 GB of 16 GB VRAM). Estimated 100-200+ tokens/second.

Full MCTS experiment (164 problems x 50 iterations x 5 candidates): ~15-25 GPU hours naive, ~5-10 hours with vLLM batching. Within Kaggle's ~30h/week GPU quota.

CPU inference: 30-80 t/s with Q4 quantization. Viable for prototyping, not for full sweeps.

**Key practical findings:**
- T4 does NOT support BF16 — must load as FP16 explicitly
- Instruct model (0.5B-Instruct) is better for code generation than base
- HuggingFace Transformers is simplest on Kaggle; vLLM for maximum throughput
- Two 0.5B models (policy + reward) fit easily on T4 (~2 GB total)
- LoRA fine-tuning of 0.5B on T4 is feasible (2-4 GB with gradients)
- Kaggle: T4 x2 (16 GB each), ~30h/week GPU, ~12h max session

**Comparison to published papers:**
- ReST-MCTS*: Requires 2x 7B models — does NOT fit on T4
- AlphaCode: 1M samples, 41B model — completely infeasible
- S* largest: 8 H100 GPUs for one day — infeasible
- CodeT: Generate N + test — FEASIBLE on T4 with 0.5B
- ACECODER: 80 RL steps on 7B — feasible with 0.5B + LoRA on T4

**Evidence:** Model specs from HuggingFace, T4 specs from NVIDIA, llama.cpp benchmarks, S* paper compute section.

**Not verified:** Exact tokens/sec for 0.5B on T4 (derived, not measured). Exact 2026 Kaggle quotas.

### 2026-09-13 — Novel Directions Gap Analysis

**Subagent question:** What are the genuine GAPS in program synthesis that a resource-constrained researcher could exploit?

**Answer:**

**Four genuine gaps identified, ranked by strength:**

**GAP 1 (STRONGEST): Confidence-Calibrated Program Synthesis**
- No published system uses confidence to gate synthesis strategy selection at test time
- ECS demonstrates perfect calibration: >0.6 confidence → 100% accuracy
- Closest work: Functional Entropy (EMNLP 2026) is post-hoc, not during synthesis
- Complementary positioning: "proactive calibration" vs "retrospective UQ"

**GAP 2 (STRONG): HDC for Program Synthesis**
- arXiv search: 0 results for "hyperdimensional computing program synthesis code"
- Doug paper (ICCM 2025) is only related work, at cognitive science venue
- ECS's HDC encoding of code structural features is completely novel in ML venues
- HDC + spreading activation for cross-domain transfer has no precedent

**GAP 3 (STRONG): Multi-Strategy Synthesis with Adaptive Selection**
- No published system adaptively selects between qualitatively different synthesis methods
- ECS has 5 methods: constraint, compositional, execution-guided, induction, neural
- Compositional achieves 100% precision on its problems, constraint 26% — COMPLEMENTARY
- Zero overlap between methods (RESULTS.md line 194)

**GAP 4 (MODERATE): GWT for Program Synthesis**
- No GWT + program synthesis papers exist
- Free-energy auction for synthesis coordination is novel
- Risk: reviewers may see as "engineering choice"

**GAP 5 (WEAK): Self-Improving Without Training**
- Reflexion (NeurIPS 2023) achieved 91% HumanEval with verbal reflection
- ECS differs in mechanism (HDC + GWT vs verbal) but needs stronger results

**Key citations for framing:**
- Rao et al. (arXiv:2512.22568, Dec 2025): position paper calling for exactly what ECS implements (actions + compositional structure + episodic memory)
- SE-GA (ICML 2026): memory-augmented self-evolution publishable at top venue
- LLM-Modulo (ICML 2024): neuro-symbolic framing accepted at top venue

**68.9% internal success rate:** ECS gets the algorithm right 69% of the time but fails on function naming. Engineering fix would dramatically improve measured performance.

**Evidence:** arXiv searches (6 results for code UQ), Functional Entropy and UA-ChatDev papers verified, Reflexion confirmed at NeurIPS 2023.
